# Contributing

Thank you for being interested in AccessibleGoPro.

This project is meant to be collaborative, open, and accessibility-focused. The goal is to make GoPro cameras more usable for blind and low-vision people through an accessible iPhone app and a strong spoken user experience.

## Ways to contribute

You can help in several ways:

- iOS and Swift development
- GoPro communication and API work
- VoiceOver accessibility design
- spoken feedback and UX design
- blind-user testing and feedback
- settings mapping for different GoPro models
- documentation and onboarding
- issue triage and roadmap feedback

## Recommended first tasks

If you are new to the project, the best first tasks are:
- learn the current GoPro connection flow
- review the settings map and list the most important settings to support first
- help improve the VoiceOver and spoken feedback design
- test the app with a GoPro and provide accessibility feedback
- document which settings are easiest or hardest to read aloud

## Priorities for contributors

### High priority
- connection to GoPro
- battery and status announcements
- recording start/stop flow
- settings readout and modification
- VoiceOver labels and hints

### Medium priority
- settings categories and navigation
- error handling and recovery
- haptic feedback design
- presets and common workflows

### Future work
- advanced settings and workflows
- voice command support
- Android experimentation
- broader platform support

## Developer expectations

When contributing, keep accessibility in mind for every change:
- can a blind user understand the result?
- is the state spoken clearly?
- can the user complete the task without looking at a screen?
- does the feature require visual inspection?

If the answer is yes to those questions, the feature likely needs more thought.

## Community expectations

This project is especially interested in user feedback from blind and low-vision people. We want to build based on real needs, not only technical assumptions.

## Suggested workflow

1. Open an issue or start a discussion
2. Describe the problem or feature clearly
3. Explain how it affects blind users and accessibility
4. If you can code, propose a simple implementation path
5. Keep documentation updated as the project changes

## Communication

Be respectful, constructive, and accessibility-first. This project is about real usability and real independence.
